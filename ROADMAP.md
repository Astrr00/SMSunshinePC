# Roadmap

Goal: a native Windows x86-64 port of Super Mario Sunshine (GMSJ01) built from the matching decomp (`sms/`), with Aurora replacing the GameCube SDK (`sunshine-pc/`). Launcher, mods, settings, unlocked framerate, widescreen, playable end to end. No game data in this repository.

Status legend: DONE = observed artifact, PART = partly working or unverified, OPEN = not working.
Last updated from observed state (see `sunshine-pc/docs/status.md` section 0 for evidence).

## Working rules (apply to every phase)

1. **Gates before any push**: matching DOL SHA-1 `9f5a8caf56f5356aeac9d3ed28bf8de976a03625` unchanged; strict link with 0 unresolved symbols; TEMP-DEBUG gate: `git grep -n TEMP-DEBUG -- sms/src sms/include sunshine-pc/src sunshine-pc/include` prints nothing (bare `git grep TEMP-DEBUG` always hits docs and `tools/verify.py`); fresh-clone build passes. `python sunshine-pc/tools/verify.py --matching` from the repo root (or `sunshine-pc\tools\verify.cmd --matching`, which loads the MSVC environment first) runs `ninja -k 0` in `sms/` and checks the DOL SHA-1, the TEMP-DEBUG grep, the Aurora series (presence, `--check` count vs the tracked patches, clean `patches/aurora`) and the line endings of the changed files, plus the headless tests and the boot smoke; one PASS/FAIL/SKIP line per step, exit 1 on any FAIL. Until its line-ending step is proven, also check the touched files with `git ls-files --eol` by hand. The strict link (`python tools\locked.py cmd /c tools\_strict.cmd` from `sunshine-pc`) and the route smoke runs stay manual.
2. **Short tasks**: every agent task is one concrete deliverable time-boxed to ~30 min (edit→build→run→evidence at least every 15 min, one line per cycle in `sunshine-pc/build/progress.log`); it then reports and the next step becomes a new task.
3. **Concurrency**: at most 3 agents that build the port or run the game. Decomp-only agents (single-unit mwcc + objdiff, ~1 s per compile) may run up to ~13 at once on the old 16-thread PC; the current PC has 6 logical processors (`os.cpu_count()` 6, measured 2026-10-12, load already 100 % with two build/run agents), so run at most ~4 at once there and only while the load stays below about 60 % (lead's policy); check load before adding, ~45 min per task, one progress.log line per finished function. Each agent owns whole units; shared headers through one owner. Multi-file Aurora work happens in a private copy (`-DSUNSHINE_AURORA_DIR=<copy>`) and lands in one step. Timing measurements (fps, logic rate, latency) are taken only while no other agent runs, and with `AURORA_SCREENSHOT_EVERY=` (empty) in the `route.py` command: its default screenshot monitor is the largest measured cost to the logic rate (LogicRate2, 2026-10-13).
4. **Evidence**: a feature counts as done only with a log excerpt or screenshot. Dev hooks are named as such.
5. **Decomp changes**: `#ifdef TARGET_PC` for port behaviour; asm-proven decomp bugs are fixed unguarded only in NonMatching units, with an `// asm 0x<addr>` comment.
6. **Saves**: tests use a temp save directory, never the user's `%APPDATA%\Sunshine\saves`.
