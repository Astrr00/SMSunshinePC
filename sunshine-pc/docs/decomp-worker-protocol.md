# Decomp worker protocol v3 (Super Mario Sunshine GMSJ01, repo root = the folder containing `sms/` and `sunshine-pc/`)

## Goal (user rule, latest)
Every non-100 % GAME function (sms/, mwcc decomp; also PC-valid with clang-cl, keep every `#ifdef TARGET_PC`) must have BEHAVIOUR equal to retail, proven from the retail asm and recorded as `logic-verified` in the ledger. Byte-identical is preferred but NOT required: where it is not reachable you may use your own code (non-retail helpers/wrappers, extra locals, restructured control flow, header edits) as long as behaviour equals retail. Codegen score is only a hint; spend NO effort on codegen-only residue beyond ~8 builds per function. Matching units stay 100 %, DOL SHA-1 stays `9f5a8caf56f5356aeac9d3ed28bf8de976a03625`. Shared/JSystem headers may be edited when it helps (rebuild every includer via `--build`, no drop in Matching units; tell the header owner agent if one is named). No MSL/MetroTRK/THPPlayer/dolphin SDK edits.

## Time/budget discipline (most failures came from these)
- Do NOT stop early. Process units until your function list/claims are done or you have done >=4 units, then give the FULL final report (counts, fixes with asm addrs, ledger rows). A final answer that only promises a report is a failure.
- Never print raw objdiff JSON or whole .s files (`--diff` is compact). Read retail asm only by `read path:from-to`.
- After every source edit: `--build <unit>` and confirm no other function of the unit dropped; if one dropped and the edit is not asm-proven logic, undo YOUR edit (restore your saved function text; never whole files from git).
- Stale objects: `--diff/--check` read the LAST built object. Always `--build` first.

## Tools (python, from repo root, all subprocesses hidden: creationflags 0x08000000|0x4000)
- `python sunshine-pc/tools/decomp_queue.py claim <You>` next unit; `claim <You> --quick` unit with most >=99 % functions (fast wins); `claim <You> <unit>` specific unit (prints `CLAIMED_BY x` if taken: skip it); `hold <You> <unit>...` same check for several; `release <You> <unit> <note>`; `free <You>`; `status`.
- `python sunshine-pc/tools/decomp_queue.py ledger <unit> "<bare fn name>" <pct> <status> <You> "<evidence>"`. The tool downgrades `logic-verified` rows lacking `branches mapped` (or `no branches`) to partial and stores pct 100 as `matched`.
- `python sunshine-pc/tools/decomp_triage.py --build <unit>` (single-unit mwcc, per-function %), `--diff <unit> <sym|demangled-substring> [ctx]`, `--check <unit> <sym>` (call order, vtable slots, fused vs unfused FP, opcode histogram, pool constant VALUES), `--branchscan <unit>` (branch-sense mismatches after identical compares), `--immscan <unit>` (compare immediates / field displacements).
- `python -m m2c.main --target ppc-mwcc-c++ -f <mangled> sms/build/GMSJ01/asm/<Dir>/<Unit>.s` (retail draft). Upstream bodies: `../sms-upstream/src` (sibling folder). Permuter: `cd sunshine-pc && python tools/permute_fn.py <unit> <sym> --seconds 600 --jobs 2` (>=97 % reg-only functions).
- Progress: one line per finished function in `sunshine-pc/build/progress.log`: `HH:MM <You> <unit> <fn> <before%>-><after%>`.

## Loop per unit
1. Claim. `--build`. List non-100 functions. Do `partial (pending review)` + `branch check pending` rows first (fast promotions: map branches, `--check`, re-ledger).
2. Per function, lowest % first:
   a. `--diff`, `--check`, `--branchscan`, `--immscan`.
   b. REAL BUG CLASSES (fix in source with `// asm 0x<addr>`; semantics beat score): inverted/missing branch (mismatched bne/beq after identical compares; `b` landing in a different block = misplaced braces); wrong switch case set (differing binary-search pivots / jump-table order); wrong member / field offset (onHitFlag vs onLiveFlag, mVelocity vs mLinearVelocity); this-vs-param base register; wrong vtable slot; swapped/different call arguments or matrix index (mtx[3][0] vs mtx[0][3]); wrong constant or pool value; missing/extra call or store; wrong return value; wrong joint/material/name accessor; signed vs unsigned compare; unexplained frame-size gap (look for missing locals/calls, not just padding).
   c. If our code is structurally far from retail: rewrite from the m2c draft until behaviour is equal.
   d. Codegen-only residue (register/stack/schedule, header inline vs retail out-of-line, fused FP only where retail's choice is documented) -> promote.
   e. Near-100 % stack/reg-only functions: pad recipes close many (`char trash[N]` unused local, declaration order, temp locals; e.g. bosseel/bosswanwan/MapObjBianco 17+12 functions) — max 8 builds, then permuter, then move on.
3. `logic-verified` evidence MUST state: `check OK` (or each item explained), `branches mapped` (taken/fallthrough code traced against retail, sense equal), calls in order incl. vtable slots, constants/pool values, field offsets, loop shape, return value; for stack-only residue also `stack remap injective`.
4. Known limits (not worth effort): JGeometry TVec3/TUtil out-of-line (per-call-site inline choice; HeaderLab proved no header mechanism), pragmas inert for header-defined inline callees, static pool/string layout shifts (`addi` into rodata with a constant delta = pool layout, benign).
5. Release the unit; claim the next.

## Rules
- Hold a unit before editing it; edit only held units' files (+headers as above). No plain `ninja` runs (the lead runs the gates), no configure.py edits, no git writes (read-only `git show/diff/log` ok), no game runs (decomp agents), no files in sms/ root, delete your scratch files. - Final report: units, functions before->after %, bugs fixed (asm addr), rewritten functions, ledger rows (counts), still-unproven items with reason.

## Recipes found in rounds 2-3 (observed, 2026-10-12)
- `char trash[N]` pad: a function-level pad must be declared AFTER the local that has to sit higher in the same scope. A pad at the top of the function only grows the frame; a pad declared after a local places it lower. Nested-block pads often have no effect.
- String-pool / immediate-only diffs (`addi rX,r31,0x...`, 99.9x % loadAfter/__ct): `-inline deferred` emits functions and the string pool in REVERSE source order, retail's pool is forward. Reverse the top-level function order of the .cpp (keep `#pragma dont_inline on/off` pairs around their function), then check every function of the unit; revert if anything else drops (cannon.cpp: loadAfter and SaveLoadParams::__ct to 100 %).
- A static table that is const in our source but in `.data` in retail must be non-const (popo createModelData).
- A local `const TNerveBase<TLiveActor>*` for the `theNerve()` compare fixes the operand order (bosspakkun receiveMessage).
- `(mLiveFlag & X ? 1 : 0)` inline instead of `checkLiveFlag2` removes a `clrlwi.` vs `cmpwi` row.
- Split a float product into separate statements to avoid `fmadds` fusion; merge to get fusion.
- Known limits (do not spend builds): header-defined inline callees ignore `#pragma dont_inline` / `inline_depth` per function under `-inline deferred` (a file-wide `inline_depth` pragma at the end of the .cpp works but changes every function of the unit); TVec3/TUtil out-of-line vs inline per call site; out-of-line `TNerveBase` ctor in inlined `theNerve()`.
- `scaleAdd(scale, b, c)` is `this = b + c*scale`; the one-argument `TMtx34::concat(b)` is not `this*b`: check call sites against the retail operand order.
- Stack-slot rule (TempSlot, measured on EventWatcher evGameOver and MapObjMonte TSwingBoard::initDraw): mwcc places NAMED locals top-down in declaration order (first declared = highest address, later declared = lower) and ALL expression/inline temps (e.g. the TSpcSlice bound by `push()`, a `(GXColor){..}` literal argument) BELOW every named local, in order of first use. So a `char trash[N]` pad of any size, position, element type, or nesting always lands ABOVE the temp (evGameOver: nopad/pad8/pad0x10/pad0x18/two pads/int/double/volatile/inner-block/after-use pads all give temp at 0x14, frame 0x28..0x48; retail has temp at 0x24). To put the temp ABOVE the pad, make the temp a named local declared BEFORE the pad: `int slot[2]; char trash[0xc]; ... slot[0]=0; slot[1]=v; interp->push(*(TSpcSlice*)slot);` gives temp 0x24, 100 %. A `TSpcSlice s;` local does NOT work (its ctor stores run at the declaration, before the calls). EventWatcher.cpp has the macros `SLICE_SLOT` / `SLICE_PUSH(interp, v)` (PC build: plain `push`, since TSpcSlice is 16 bytes there). Per function find the pad size with a 0..0x2c sweep (evGameOver 0xc, evForceCloseTalk 4, evLaunchEventClearDemo 4). Only fits functions whose sole temp is the pushed slice; pop()/getDataInt temps are separate and stay unchanged.
- Dead temps: `if (0) { (void)(GXColor) { 1, 2, 3, 4 }; }` emits no code but reserves an 8-byte expression-temp slot BELOW the later live temps (MapObjMonte TSwingBoard::initDraw: temps 0x10 -> 0x18, with a named `int pad4;` after the texture the object is 99.931 -> 99.969 %). Every dead temp rounds up to 8 bytes (char[1], GXColor, Vec(12)->16), so offsets 4 mod 8 (retail 0x1c) are not reachable this way; dead `TSpcSlice()` temps / `char[N]` literals inside `if (0)` do NOT shift later temps (slot reused / counted as named).

## Permuter (automatic base.c, 2026-10-12)
- `cd sunshine-pc && python tools/permute_fn.py <unit> "<mangled sym incl. class and params>" --seconds 600 --jobs 2` (e.g. `mario/Enemy/Koopa "execute__16TNerveKoopaTurnRCFP24TSpineBase<10TLiveActor>"`; quote the symbol, it contains `<>`). `--build <unit>` first and claim the unit: it reads sms/src/<unit>.cpp, extracts the function, writes `<decomp-permuter>/nonmatchings/<sanitized sym>/{base.c,defs.h,head.h,tail.h,meta.json,compile.sh,settings.toml,target.o,run.log}` and runs the permuter (needs `pip install toml`; the permuter is found at `../decomp-permuter` or `../SunshineHandoff/extra-repos/decomp-permuter`).
- base.c is C syntax only because pycparser parses it: member `Cls::f(a)` becomes `f(Cls* this_, a)`, `A::B<T>` chains become `#define` aliases (defs.h), unknown types become `typedef int X;` stubs. `compile.sh` rewrites every candidate back to C++ (`Cls::f(a) const`, `this_`->`this`) and compiles head.h (unit source above the function, with its `#pragma`s and earlier inline candidates) + defs.h + candidate with the unit's exact mwcc flags (incl. `-inline deferred`). `--scope unit` also appends the rest of the unit (slow, most faithful); `--scope includes` only the #includes (fast, loses unit-local helpers). Ctors/dtors/operators are not supported (write base.c by hand and run without `--regen`; a hand-edited base.c is kept). `--nth N` picks among overloads; `--regen` rebuilds base.c after you edited the .cpp.
- Score 0 at start = permuter already sees identical code (the diff is reloc/pool only). Found variants are written to `nonmatchings/<dir>/output-*/source.c`: translate the diff back into the .cpp (`this_` is `this`, aliases are the original `A::B<T>`), `--build`, check no other function dropped. Log lines `internal permuter failure ... KeyError` are harmless: the permuter lacks types for unknown members/calls and just skips that mutation.
- No float literals in dead temps: `(Vec){1,2,3}` / float structs go into the constant pool and shift later string offsets (fireWanwan SaveLoadParams ctor 0x28 off); use int-only temps (`GXColor`, int structs).
- Ledger key = full demangled symbol (bare names like `execute` collide across nerve classes); `logic-verified` only after an individual review.
- Open bug candidates for an asm-trace task: `TSmallEnemy::changeMove` switch constants (retail 2/1/4 vs ours 3/2/5, asm 0x8027EB6C), `TConsoleStr::processGo` (retail offsets 0x34..0x40 vs ours 0..0xc), `TNameIndParCallback::execute` (load at 0 vs 0x10).

## Agent workflow v4 (lead decision 2026-10-12, from rounds 1-7)
Observed problems: agents hit the request limit near 1 h and lose their list; several agents wait for the same held unit; scripts wrote ledger rows without a read; a header edit broke all includers twice; a swapped operand hid behind a register rename; pool-value diffs are invisible to objdiff.
- Disjoint lists: the lead assigns whole units per agent up front. Do not claim units outside your list. A refused claim means: skip the unit, name it in the report.
- Time box: about 30 min or 8 units per agent, then final report. The lead starts a fresh agent for the rest of the list. Do not idle and do not poll.
- Order per unit: `--build`; `--check` and `--immscan`/`--branchscan` first (cheap, they find pool values and branch senses); then read the function against the asm, lowest % first. Byte-recipes: at most 4 builds per function.
- Register-rename diffs: decode compare operands and argument registers before calling a row `register-only`. A swapped operand or argument is a real bug.
- Ledger: `logic-verified` only after you read the function (evidence names what you read: branches, calls, constants, offsets). Diff statistics alone give `partial (pending review)`. Never write rows from a script.
- Headers: only the header owner edits headers. Others send a wish in the report. Never put `(void)(GXColor){..}`/float literals into a header. After a header edit the owner rebuilds every includer (`grep -rl`) and reverts on any drop.
- After every edit: `python sunshine-pc/tools/decomp_triage.py --build <unit>`; revert if another function dropped.
- PC safety (observed round 7): never replace `readU32()`/`>>` by a raw multi-byte `stream.read(&x, n)` without the `#ifdef TARGET_PC x = stream.readU32(); #else stream.read(..) #endif` branch (raw read skips the big-endian swap; `TMapEventSink::load` crashed). Never restructure control flow so a state loses an invariant other code relies on (`TModelWaterManager::move`: state 2/3 particles need `unk2914[i]` set). Retail asm equality in a diff is not proof the PC build still runs. After a round: run Route 70; on a new crash revert the round's diff and bisect, do not add null guards.
- Report format (max 12 lines): bugs fixed (unit, function, asm address, ours vs retail); units fully read; units left open with reason; header wishes.
