## 7. Crash fixed: glyph replacement cached in a JKR heap (observed)

- Cause (read in source, confirmed by the fix): `buildGlyphTimg` (`sms/src/JSystem/JUtility/JUTResource.cpp`) built the replacement `ResTIMG` for the button glyphs with `new (0x20) u8[...]`, i.e. in the current **JKR heap**, and kept the pointer in the static table `sGlyphTimg` for the whole run. The title / option-map heap is freed and reused at the stage change; later `JUTTexture::storeTIMG` read a foreign block as a BTI header (`w=54675 h=3007 fmt=221`), Aurora then asked WebGPU for an impossible texture (`Resource allocation size 18446744073709551615`). It only showed in the full flow because only there the cache is filled before a stage change; a dev start fills it inside the stage.
- Fix: the block now comes from `_aligned_malloc` (host memory, never freed, as the comment always claimed).
- Evidence: before, f01-f06 (6 of 6 full runs) died at the first spray with the same texture values. After, `f07` (`12_tutorial_full.dev`, no start/skip switch) ends with `done at tick=8507`, exit code 0, and 0 of each of `corrupt texobj`, `suspicious static texture`, `WebGPU error`, `overrun`, `fatal exception`. `wash.png` shows the M on the first block washed off and the water button with the Xbox glyph. `h01` (`15_full_diag.dev` with `SUNSHINE_DEV_SKIP_MOVIES=1`) passes too.
- Gates after the fix: DOL SHA-1 `9f5a8caf56f5356aeac9d3ed28bf8de976a03625`, 11 013 / 12 881 functions, 445 / 736 units, strict link 0 unresolved, `TEMP-DEBUG` 0 (the `J2DPicture.cpp` diagnostic was removed again), Aurora series 10 patches.

- `airport1` `scene.bin` holds an `AirportEventSink`, a `Pollution` object, four `nozzleDoor`s and a GateKeeper `ゲートキーパー（ビアンコ）` at **(-1500, 300, 1500)**, i.e. inside the y=300 goop basin. `TAirportEventSink::watch()` (`sms/src/MoveBG/MapObjAirport.cpp:66-80`) waits for that GateKeeper's `LIVE_FLAG_DEAD`; then the building rises, the goop layer decays and `finishControl()` makes a Shine appear (`シャイン（落書き用）`). So the way out of the tutorial is: kill the boss, collect the Shine (the flow after the Shine is still unobserved).
- Real game bug found and fixed on the way (observed): spraying goop crashed the game (`0xC0000005` in `TPollutionLayer::cleaned`, `PollutionLayer.cpp:203`, run x06, via `TMario::gunExec`). Cause: `static pos[10]` is indexed up to 10 (`now_pos_no` wraps only above 10, retail asm 0x801F34A0 `cmpwi r0,0xa`); on x64 the 11th element overwrote the neighbouring offset tables and `mPollutionMap` was read out of bounds. Fix under `TARGET_PC`: `pos[11]`. Run x07 (same route) ends with `done at`, exit 0. DOL SHA-1 `9f5a8caf…` unchanged.
- Boss behaviour measured with the new `[..-boss]` log (x08-x11, `18_gatekeeper_probe.dev`, airport/1 dev start): start `hp=3`, asleep (bck 0xA, body vulnerable); the first water hits (`unk154`=3) wake it (bck 4 -> 0 -> 0xF -> 0x10 -> 0xC -> 0x6 -> back to 0xA about 600 ticks later); `hp` stayed 3 in every run.
